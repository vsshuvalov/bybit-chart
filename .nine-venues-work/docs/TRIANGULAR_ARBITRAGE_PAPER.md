# Треугольный арбитраж — PAPER-прототип

Контур ищет ценовое рассогласование внутри одной spot-биржи. Для стартового
актива `A` допустимый маршрут содержит ровно три разных актива и три рынка:

```text
A → B → C → A
```

Например, при наличии соответствующих рынков это может быть
`ETH → BTC → BRL → ETH`. Движок проверяет также обратное направление.

## Как проходит один скан

1. Для каждой выбранной биржи выполняется публичный запрос всех spot-тикеров:
   Bybit, Binance, OKX, Bitget, Huobi, KuCoin, MEXC, BingX или Gate. Поскольку
   общий ответ Gate не сообщает размеры лучших заявок, для него дополнительно
   подтверждаются реальные первые уровни стаканов у ограниченного набора до
   20 кандидатов, включая резерв ликвидных кросс-пар.
2. Невалидные и нулевые котировки отбрасываются. Объём приводится к
   приблизительному USDT-эквиваленту, когда в снимке есть путь конвертации.
3. Из полного рынка выбирается до 50 наиболее ликвидных пар. Отбор сначала
   добавляет все три ребра ликвидных треугольников, содержащих стартовый актив,
   а остаток заполняет следующими ликвидными парами. Поэтому лимит не
   превращается в набор несвязанных `.../USDT` рынков.
4. Для каждой пары строятся два направления: продажа base по лучшему bid и
   покупка base за quote по лучшему ask.
5. Движок перебирает циклы из трёх конвертаций, ограничивает стартовый объём
   доступным top-of-book количеством каждой ноги и списывает taker-комиссию
   после каждого обмена.
6. Возможность показывается, только если результат после трёх комиссий и
   risk buffer превышает заданный порог.

Непрерывный REST-монитор работает с интервалом не меньше 10 секунд: полный
24h-tickers запрос Binance имеет высокий request weight, поэтому более частый
опрос создавал бы ненужный риск rate limit. Статус локального API интерфейс
может читать чаще — это не вызывает запросов на биржи.

Упрощённая формула:

```text
final = leg3(leg2(leg1(start)))
net PnL = final - start - risk buffer
net edge = net PnL / start
```

## PAPER-исполнение

При `auto_execute=true` лучший ещё не исполненный снимок применяется к
виртуальному балансу атомарно: стартовый актив списывается, итоговый объём
того же актива зачисляется, а все три ноги попадают в журнал. Повторное
исполнение тех же снимков блокируется.

Переключатель `use_fee_token_discounts` по умолчанию включает тот же
централизованный PAPER fee-профиль, что и межбиржевой экран. Снижение ставки
учитывается на каждой из трёх ног цикла. Это what-if в стоимостном эквиваленте
(комиссия каждой ноги выражена в получаемом на ней активе):
система предполагает включённую опцию и достаточный баланс BNB/BGB/HTX/KCS/MX
или GT, но не создаёт эти токены и не моделирует их покупку либо курсовой риск.
Bybit MNT не применяется, потому что API-ордера официально исключены; для OKX
и BingX скидка токеном не подтверждена. Полная таблица и официальные ссылки
приведены в `ARBITRAGE_PAPER_PROTOTYPE.md`.

Никаких API-ключей, приватных endpoint или методов отправки ордеров в этом
проекте нет.

## Ограничения прототипа

- All-tickers REST — не атомарный стакан всех инструментов. Между обновлениями
  трёх котировок может пройти время. Поэтому маршрут отклоняется, если метки
  времени его ног различаются больше чем на 2 секунды.
- Используется только лучший bid/ask и заявленный объём первого уровня.
- Фактические шаг количества, minimum notional и разные fee tiers конкретного
  аккаунта пока не загружаются.
- USDT-эквивалент 24-часового объёма нужен для ранжирования, а не для расчёта
  прибыли.
- Буфер риска лишь моделирует часть slippage и задержки; он не гарантирует
  исполнение.
- BRL и другие fiat/stable рынки есть не на каждой подключённой бирже, поэтому
  конкретный пример маршрута появится только там, где существуют все три пары.

Положительный одиночный сигнал не подтверждает стратегию. Оценивать теорию
нужно по серии независимых снимков, итоговому PAPER PnL после комиссий,
частоте stale/error сценариев и устойчивости результата к повышенному
slippage. Следующий безопасный этап — WebSocket shadow mode и актуальные
instrument rules; реальные аккаунты подключаются только отдельным модулем
после проверки риска.
